Internal overview

OxiNote

A Markdown notes application written in Rust. It opens an existing Obsidian vault. This page describes what version 0.3.0 of the repository does. License: MIT or Apache-2.0.

The repository

Obsidian is a proprietary application, Electron and TypeScript, with closed source. OxiNote does not modify it. PLAN.md describes a reimplementation: the same Markdown files, the same .obsidian/ folder, and the link, embed, tag and callout syntax that folder expects.

The repository text is in French. The Cargo workspace has seven crates, from the vault on disk to the oxinote-app and oxinote binaries. docs/AGENTS.md still marks oxi-app as in progress; it marks the other six crates complete.

Out of scope for now, according to the plan: Sync, Publish, and JavaScript plugins already written for Obsidian.

Install and updates

GitHub releases contain the application and the CLI. .github/workflows/release.yml builds for:

  • Linux x86_64
  • macOS Apple Silicon
  • macOS Intel
  • Windows x86_64

On Ubuntu or Debian, the .deb package adds the application to the menu and oxinote to the terminal.

At startup the application asks the releases/latest API at most once a day. If the tag is newer, it downloads the archive for this platform, checks it against SHA256SUMS.txt, and replaces the installed files. The new version runs after a restart. Settings, About: “Install automatically” (the default in the code), “Notify only”, or “Off”. A .deb install under /usr, a folder the process cannot rewrite, or a translocated macOS app, is only reported.

To publish: set version in Cargo.toml ([workspace.package]) to the same number as the tag, then run the Release workflow (v0.1.0, or v0.1.0-rc.1 for a pre-release) or push a vX.Y.Z tag.

The application

oxinote-app is an eframe / egui interface. Writing is Live Preview or Source mode. Reading is a separate mode. The command registry covers formatting, lists, checkboxes, find and replace in the note, and folding. Heading navigation has two layouts, named in settings as a floating outline and a loupe. Typed properties are a panel at the top of the note.

Side panels show the file explorer, search, tags, backlinks, outgoing links and the outline. The quick switcher and the command palette open a note or a command. Bookmarks, daily notes and templates each have a command. Tabs sit in groups. The theme follows the system, or stays light, or dark.

Nine core plugins are read and written in .obsidian/core-plugins.json: backlinks, bookmarks, daily notes, graph, outline, properties, tags, templates, word count. An id this code does not know is kept. The vault folder is watched; events are debounced before they are applied.

A PDF opens in a tab. The engine is hayro, in Rust, with no system library. The open comes from a link or an embed, with a page and a zoom. Git backup calls the system git binary on a background thread: automatic commit, .gitignore, per-note history and restore. There is no remote.

Markdown

The parser is pulldown-cmark (CommonMark and GFM), plus a pass for Obsidian syntax. Each kept element has a byte span in the original file, so a link can be rewritten without moving the rest.

YAML frontmatter, between --- on the first line, is converted to JSON. The code recognizes aliases / alias, tags / tag, and a value that is exactly a wikilink. It also recognizes [[target#subpath|label]], embeds ![[…]], internal Markdown links, tags #tag/child, block ids ^id, tasks, highlights ==…==, comments %%…%%, callouts > [!type] and math. Those marks are not collected inside a code span or code block, inside math, inside an HTML comment, or inside a %%…%% comment.

Editing a property rewrites the frontmatter and leaves the body. Types read and written in .obsidian/types.json are text, multitext, number, checkbox, date, datetime, aliases and tags. Renaming a tag onto a name that already exists merges the two. Renaming a note or a folder updates links that point at them.

A link is resolved in this order: exact path, then a unique filename. If several files remain, the one closest to the source folder wins, then alphabetical order.

The oxinote command

Every subcommand takes the vault folder as its first argument. Search accepts tag:, path:, file:, a quoted phrase, -exclude, OR and /regex/.

CommandEffect
statsNotes, attachments, links, tags, orphans, words.
searchLines as path:line: text, or JSON.
backlinks, links, unresolvedIncoming links, outgoing links, missing targets.
tags, tagCounts, tree, rename, add or remove.
props, propVault properties; set or remove one on a note.
orphans, findNotes with no links; fuzzy match on name, path or alias.
graphJSON or Graphviz, local graph, optional force-directed coordinates.
renameMoves a note and updates links. --dry-run writes nothing.
dailyOpens or creates the daily note and prints its path.
exportStatic HTML site. Wikilinks become relative links.

Planned in PLAN.md

The roadmap, after what the plan marks as done, is not in the application today:

  • Bases: table views in the .base format.
  • Canvas: a whiteboard in the .canvas format.
  • Citations: BibTeX or Zotero, [@key], a reading note.
  • PDF, continued: text selection, text search, embeds in Live Preview, annotations. The tab reader already exists.
  • Remote Git: push and pull. Local backup already exists.

Phase 3 of the plan also names a plugin API as Rust traits and then WASM, CSS themes and snippets, and a response-time target on 10,000 notes. The agent guide does not mark those as shipped. The light, dark and system theme is in settings.rs; this page does not describe a CSS theme loader.
